## Decisions and acceptance

- Saved replies: personal (owner only, 50/account) or team (100 total); title 3–120 and plain-text body 1–4000; immutable scope on edit. Team edits/deletes allowed to Support. Strict input, timestamp compare-and-save, serialized quotas. Creator deletion cascades owned templates. Each create/edit/delete uses existing append-only Support activity, with null ticket/ref for template events and template UUID only in the metadata (never reply content). This relaxes the existing audit nullability/closed-action constraint, not a second audit table.
- Insert: a Support-only preview resolves only literal {code}/{name}, non-recursively, from the selected report; other braces stay literal, unknown/deleted author uses “there”. Expansion and insertion cannot exceed 4000. Insertion appends to the editable draft; never sends. Route/account/unmount cancellation and local error/duplicate-action handling.
- Merge: one nullable merged_into_id reference; no self, missing target, chains, cycles, or moving an already merged source. A source with existing duplicates cannot itself merge. Multiple leaves may share one surviving report. Merge/unmerge acquire a common transaction lock and row locks; database guards also refuse invalid topology. Compare source/target timestamps before merge, source before unmerge. Duplicate becomes Resolved; unmerge clears the link and opens it. Both append fixed “System:” messages to the original conversation and audit actions; transactional status notifications use existing kinds.
- Strict privacy: no messages are copied or combined. Only report code/id may cross. Reporter GET of a surviving link resolves their own most-recent linked conversation if they do not own the survivor. Returned content/identity remains their own; writing is authorized against that original conversation. Original links remain readable. Merged duplicates remain resolved while private follow-up messages continue; these messages do not reopen or expose the survivor. Explicit unmerge is needed before Support reopens a duplicate. Unmerge removes alias access immediately. Support can navigate linked duplicate conversations separately.
- Export: own personal templates and own report merge metadata only; no team/other reporter text. Account deletion cascades owned templates. No owner database migration by the agent.
- Verification: real PostgreSQL endpoints/privacy/role refusals/placeholders/quotas/races/stale edits/rollback/export/deletion and migration up/down refusal; controlled UI and Chrome tests on isolated data, phone/laptop light/dark/keyboard; applied deliberate privacy/cycle/template-send faults; full appropriate builds/lint/types/contracts/unit/e2e plus affected Support/notifications/settings journeys. No existing assertions weakened. One heavy verification job at a time.
